Lab Exercise 3 - Fetch API
Guide Questions


1. What are the main differences between XMLHttpRequest and Fetch API?

XMLHttpRequest is the old way, where you call open() and send() and then keep
checking readyState to know if it is done, and you still have to run
JSON.parse() yourself. Fetch is the newer way, and it uses promises, so you
just call fetch() and use response.json() and you do not need to check
readyState anymore. The errors are also different, because fetch only fails
when the network fails, so if the server sends 404 or 500 you still have to
check response.ok yourself.


2. Why is the Fetch API considered more modern and readable?

Because you can read it from top to bottom like a normal sentence, since you
call fetch, check if it is ok, then get the JSON, with no readyState numbers
and no manual JSON.parse(). You can also chain the steps with .then() or
async/await instead of putting callbacks inside callbacks, and all the settings
go in one object with method, headers, and body. That is much easier to read
and change than calling open(), setRequestHeader() several times, and send().


3. What is the purpose of the .then() and .catch() methods in Fetch?

.then() runs when the step before it worked, and it returns a new promise,
which is why you can chain them, so the first one gets the response and
returns response.json() and the next one gets the data and puts it on the page.
.catch() runs when anything failed, like a network error, the error you throw
when response.ok is false, or a problem reading the JSON, and since one
.catch() at the end covers every step before it, you do not have to write error
handling again and again.


4. What happens when you send a POST request to the placeholder API?

It sends your data to https://jsonplaceholder.typicode.com/posts with the POST
method and a JSON body, and the server answers with status 201 Created and
sends the same data back with a new id, which was 101 in our test. Even though
it looks saved, JSONPlaceholder is only a practice API that does not really
store anything, so if you GET /posts/101 afterwards you get 404 Not Found,
which is also why it is safe to practice on it.
